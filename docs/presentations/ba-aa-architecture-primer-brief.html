BA / AA ARCHITECTURE PRIMER

看架构图之前：设计逻辑、业界参照与演进空间

本材料用于 BA、AA 架构图展示前的共同语言对齐。目标不是替代 Excalidraw 原图， 而是让参会者先理解「为何如此设计、如何读图、何处可演进」，再进入图面讨论。

ONE-SENTENCE POSITION

架构是价值流与职责分域的固化，不是技术清单的可视化

MSSClaw 的 BA 先回答谁用、什么业务能力、如何创造价值； AA 再回答用哪些应用模块分层承载。 分层借鉴 4A / TOGAF「业务先于应用」与 AI 平台「使用 / 配置分面 + Agent 货架」实践， 为 1.0 落地留骨架，为 2.0/3.0 留扩展口，而不是一次画满终态。

01研讨意图：为什么需要「看图前导入」

直接抛架构图时，常见失效模式是：

  • 把 BA 当成「页面菜单清单」，争论框多不多；
  • 把 AA 当成「技术选型图」，过早陷入实现细节；
  • 无法判断哪些是原则性取舍，哪些只是 1.0 过渡态。
导入页要达成的效果：参会者带着「价值流是否闭环、双壳是否必要、场景单元是否可扩展、演进口在哪里」四个问题去看图，而不是被动扫框。

02设计三问：架构为何长这样

Q1 · 价值如何发生？→ 主路径驱动

学习
→
准备
→
开干
→
沉淀

平台不是「功能仓库」，而是把个人 AI 用法沉淀为组织可复演能力。 因此 BA 以价值流为主轴；AA 的 L1/L2 必须直接承载这条链（找案例 → 样板间 → 一键打样 → 任务中心）。

Q2 · 谁用 / 谁配？→ 双壳分域

业务壳（使用面）

业务用户 / 访客：找案例、做任务、任务沉淀；场景层内偏只读浏览，开干经顶栏动作收口。

运营壳（配置面）

能力运营 / 超管：Agent·Skill·Tool 上架精选、门户内容、展示与租户治理。

这不是 UI 偏好，而是架构级取舍：避免「会配置的人」与「要打仗的人」挤在同一工作面， 也避免权限与发布门禁失控。

Q3 · 最小价值单元是什么？→ 场景样板间

BA 将「场景样板间」定义为价值单元（学习层 / 准备层 / 开干层齐套），对应 AA 的 L2 核心应用。 后续扩展优先是加场景包，而不是先加零散功能点——这决定了可复制性与 1.0「区域案例包」交付方式。

03BA → AA 映射与读图顺序

BA（业务） AA（应用承载） 读图关注点
干系人 / 四角色 应用使用面：业务工作台 / 平台运营台 / 决策消费面 是否职责清晰、有无越权面
价值流：学习→准备→开干→沉淀 主路径应用：找案例门户、样板间、做任务、任务中心 链路是否断点、开干是否收口
BC-01~05 能力域 L1–L5 模块分层 + 外部能力边界 能力是否有宿主模块、边界是否外置
1.0 业务结果 不画进技术栈；用样板与治理可验收性体现 哪些是门票，哪些可后置
建议读图顺序：BA 价值流 → BA 能力域 → AA 分层（L1→L5）→ AA 外部边界。 刻意不做的事：BA 不写技术栈；AA 不展开部署与实现细节（部署另议）。

04业界最佳实践与 AI 架构参照

以下为「借鉴其原则」而非「宣称等价某产品」。讨论时应强调取舍，不搞贴标竞赛。

企业架构方法

  • 4A 分层：BA 定业务能力与价值，AA 定应用组合（本材料聚焦这两层）。
  • TOGAF 精神：业务架构先于应用架构；能力域驱动模块划分。
  • Capability-based planning：以 BC 能力域组织讨论，避免按页面堆功能。

AI 平台常见范式

  • Consumer / Builder 分面：使用与配置分离（类 Power Platform / Copilot Studio 的角色面）。
  • Agent 货架：Agent / Skill / Tool 可发布、精选、挂载场景（类能力市场，非单点聊天窗）。
  • 编排收口：执行编排作为共享能力（AA-L5），业务应用不各自发明一套运行时。
  • 外部能力边界：模型、业务连接器、准备环境外置，便于替换与合规管控。

与「纯 Chat / 纯本地 Agent」路线的差异

  • 纯 Chat：缺场景单元与组织沉淀面 → 难支撑「学习→开干」闭环。
  • 纯本地 Agent：强本机触达，弱组织货架与审计 → 与员工助手易重叠，且非本平台 1.0 主目标。
  • MSSClaw 选择：组织场景作战平台——以 BA/AA 固化分域与货架，而不是做一个更大的对话框。

05演进与拓展性：换层不换骨架

可扩展性体现在「稳定骨架 + 可替换填充」，而不是一次画完所有未来模块。

阶段 稳定不变（骨架） 可演进（填充）
1.0 主路径、双壳、场景单元、L1–L5 分层 准备层以体外参照清单为主；区域案例包先跑通
2.0 同上，不推翻 BA 价值流 准备能力内化、L3 货架加厚、连接器扩展、编排增强
3.0 场景仍为价值单元 多区域复用、治理精细化、组织协同出口增强

扩展时优先动哪里

  • 新业务场景 → 加场景包（BC-02 / L2），少改门户骨架
  • 新能力类型 → 进 L3 货架 + 挂载关系
  • 新系统对接 → 走「外部能力边界」的 Tool/API

扩展时尽量不动哪里

  • 学习→准备→开干主路径口径
  • 业务壳 / 运营壳分域原则
  • 开干收口到任务闭环（避免场景层内随意执行）

06讨论引导问题清单

打开架构图前，可先用这些问题对齐预期；看图时逐条对照。

  1. 价值流是否覆盖「学得到、备得齐、开得动、沉得下」？断点在哪？
  2. 双壳分域是否符合组织分工？有无必须合并的例外角色？
  3. 「场景样板间」作为最小价值单元，是否支撑区域案例包复制？
  4. L3 货架与 L5 编排是否足够支撑后续能力增长，而不迫使 L2 膨胀？
  5. 外部边界（模型 / 连接器 / 准备环境）是否清晰到可交给 IT / 安全讨论？
  6. 哪些框是 1.0 必验，哪些只是占位演进口？（避免把路线图当本期范围）
