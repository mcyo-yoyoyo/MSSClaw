工具集市上架怎么评？——流程与关口

目标：能学会 · 能推广 · 能复制
原则：不安全不上 · 没价值不推 · 无试点不上 · 能用≠推荐

一句话：来源可以不同（样板间打样，或业务自建），上架标准同一套。 第3步用 ROI 判断值不值得组织推广、消耗模型资源； 第5步 小范围试点是正式上架的前提——要么先试点再上架，要么提交时必须有试点验收记录。

第1步 · 两条入口来源不同，关口同一

入口A
先评再做
需求评审 → 样板间打样 → 试点 → 再上架 先确认值得做、不重复；打样后必须完成试点验收，过关才正式上架。
入口B
先做再评
业务已做成（通常已试点）→ 核验验收记录 不再重复问要不要立项；但上架评审必须查清：有无试点、谁验收、结论如何。

第3步 · ROI上架 = 持续耗模型

Skill / Agent 上架后会反复调用模型、消耗 token。业务主管要问： 组织推广后，产出是否盖过投入？

  • 产出：省工时、缩短周期、少差错、口径统一，能否衡量
  • 投入：调用频次 × token 成本 + 推广运维
  • 结论：ROI 不够 → 不推广或只试点；够了再进质量安全关

第5步 · 试点是上架前提两条入口都要过

正式上架前必须有小范围试点。评审重点不是再跑一遍试点，而是核验 试点验收记录是否齐全、结论是否过关——须有 业务使用人员参与验收。

  • 入口A：打样后先试点，验收通过才允许上架
  • 入口B：通常已试点，申请时必须提交验收记录备查
  • 缺记录 / 未过关：驳回或退回补试点，不得直接进集市

怎么打分、怎么拍板、留下什么

记住：能用 ≠ 首页推荐
硬门槛：安全红线 · 试点验收 · ROI 说得清

怎么打分（满分100）统一尺子

①
业务价值 / ROI（25） 通用、收益、频次、可复制；收益是否盖过 token 与推广成本
25
②
功能是否完整（25） 主流程跑通、说明样例齐、依赖清楚
25
③
质量稳不稳（20） 严重问题清零；改版要重新验
20
④
安全合不合规（20） 无恶意指令、不泄密越权、权限能小则小
20
⑤
好不好学好管（10） 名字清楚、须知明白、约15分钟上手
10
≥75：正式上架可全员用；够好可申请推荐
65–74：带条件能用，默认不推荐，先整改
无试点验收：不上架先补试点记录，再评推广
<65 / 安全不过驳回，写清原因再来

业务主管重点看第3步

场景给谁用？解决什么日常问题？（一句话说清）
通用至少两个代表处，或两个职能条线能复用
收益省工时 / 缩短周期 / 少差错 / 口径统一 —— 至少一项可衡量
频次用得越频，模型消耗越大，越要算清账
ROI产出是否明显大于：token 成本 + 推广运维成本
可复制换组织主要只换数据与权限，方法不变

两类东西怎么评积木 ≠ 岗位专家

对象通俗理解直接否决
能力组件 干净可复用的「积木」 安全风险、乱要权限、高度重复
业务助手 能办完一类事的「岗位专家」 空壳、无案例、主流程不通
