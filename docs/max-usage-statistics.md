# MAX 使用统计

入口：管理后台 → 数据看板 → AI 使用统计。原有平台运营统计完整保留。

## 数据

- 复用已有 MAX 会话（app_setting / ai-knowledge-pilot），新增消息时间、调用关联 ID 与拥有者信息。
- 方案保存在原方案表，同时在会话中保留历史方案及其消息位置；后续提问不丢失已经生成的方案。
- 所有三种统一模型传输入口采集上游返回的输入/输出 Token，每次请求（包括重试）独立记入 ai-usage:call。后台生成问题、旧智库以及执行链等使用相同入口，计入平台总量。
- MAX 消息/方案生成使用 AsyncLocalStorage 关联用户、会话、操作 ID；并发请求相互隔离。
- 搜工具只在明确提交搜索且资产加载成功时保存关键词和结果卡片快照，eventId 幂等；不在输入时、恢复页面时重复采集，也不调用模型。
- 当前以 app_setting 独立命名空间持久化，未改变既有业务表，不需要数据库迁移。统计按北京时间过滤，服务端分页每页 30 条。

## 口径与边界

- 顶部累计/今日：平台模型请求已记录用量；下方时间范围不影响这两项。
- 期间人数：有新增提问的去重身份，访客使用散列标识；成功轮次以新增成功回复计数。搜工具单独计次。
- 所选时间的 Token 包含重试和方案生成。模型接口未返回完整用量时标记未知，展示已知部分，不推算历史 Token。
- 无逐轮时间的旧会话仍按最后更新时间可查询，但不虚构期间人数、轮次或用量；旧会话中新增消息从启用后正常计数。
- 旧版本未保存的历史方案或搜索快照无法补回；以后生成的方案按原对话位置展示。
- 搜索记录是客户端提交的结果快照，不用于鉴权或计费事实。归档接口仅保存有界字段，不信任客户端提供的用户身份。
- 当前查询读取轻量命名空间后聚合，适用于本机试用规模；如规模持续增长，应迁到专用明细表和日期索引。

## 查看

后端报告与详情接口只允许 super_admin；复用已有登录会话校验，不开放全站对话给普通用户。半屏抽屉复用 KnowledgeMessages、SourceCard、SolutionDocumentReader，消息只读，无发送/执行操作；来源新标签页打开，方案在抽屉内打开并返回原滚动位置。窄屏抽屉占满宽度。
