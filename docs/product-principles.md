# MSS AI 提效作战平台 · 产品设计原则

> 用途：长期共识与改版评审基准。  
> 不变层是原则；可变层是交互细节、文案、菜单开闭与短期冲刺策略。  
> 领导或需求「改来改去」时，先判断：改的是可变层，还是在否定不变层。

---

## 怎么用

1. 新需求 / 改版评审：逐条对照，说明符合哪几条、会挑战哪几条。
2. 与传统后台习惯冲突时：优先保留原则意图，并写清「为什么不做成传统样子」。
3. 原则本身不随某一版 UI 或临时演示方案漂移；实现路径可以迭代。

---

## 十条不变原则

### 1. 用户找能力，走三条货架，不走后台目录

业务入口永远是：**外部精选 / 公司推荐 / 自建集市（MSS 工具集市）**。  
后台「配置技能 / 专家 / 工具」是生产车间，不是用户逛的市场。

### 2. 角色决定工作台，不随个人偏好混用

业务工作台与平台运营台分离：业务侧不堆配置菜单；运营侧不把配置导航伪装成业务导航。  
人用什么台，由角色决定，不靠自己切换「看起来像管理员」。

### 3. 左侧组织筛选是「建设成果导航」，不是全站过滤器

领域 / 区域显性存在，是为了让大家按组织视角看见 **MSS 建设成果**，促进生态繁荣。  
它不等于传统后台左侧「过滤当前页全部列表」：在首页或外 / 内货架点选，应引导进入 MSS 集市视角，而不是顺手筛掉外链工具本页内容。  
这是刻意选择，不是漏做。

### 4. 先入库，再上橱窗

「能力可发布 / 可调用」与「出现在业务货架」是两步。  
登记、归属、发布在配置中心；上哪件货架、标题、精选、置顶在门户运营。  
禁止「一点发布就自动等于全站曝光」的隐含约定。

### 5. 数据空间与可见性正交，禁止混用开关

「开哪个租户 / 战区空间」管的是空间列表；  
「谁看得见这条 Skill / 工具 / 案例」管的是资产可见性（全员 / 本组织 / 更窄）。  
短期全员可见，改的是可见性策略，不是关掉租户配置；组织内可见，也不是用租户开关冒充 ACL。

### 6. 三角色边界不交叉污染

- **业务**：用货架、看材料、提报、执行任务  
- **能力开发**：按组织范围建设能力资产  
- **平台运营**：治理、陈列、规则与全局编排  

访客只读逛货架。完整能力只向对应角色打开，不为「演示好看」给业务用户塞运营菜单。

### 7. 材料优先于样板间

业务默认路径是：**场景 / 分类 → 卡片 → 预览 / How to / 下载或使用**。  
深度「样板间式详情」是可选进阶，不是必经页。  
提报与运营表单应对齐用户真实看到的材料字段，不为后台 CMS 习惯强迫用户填用不上的结构。

### 8. 先能用，再变厚

MVP 先保证三货架与任务主路径跑通。  
知识、记忆、自动化、工作流、租户治理入口等，按成熟度递增开放。  
「管理员默认看见一切」不是原则；「当前阶段只开必要能力」才是。

### 9. 运营门槛低于设计门槛

登记与上架优先：**必要字段 + 轻量标识（如色点）**。  
品牌 Logo、复杂视觉资产不是上架前置条件。可持续运营优先于好看的卡片皮。

### 10. 主按钮说真话，精选只改优先级

能打开就「使用」，能跑就「执行 / 打样」，否则引导 How to 或「下载使用」。  
精选与置顶只改变露出顺序，不虚构能力、不替代真实可用性。

---

## 一页版（汇报可用）

1. 用户逛货架，后台做生产  
2. 角色定工作台，业务与运营不混壳  
3. 左侧组织筛选 = MSS 建设导航，≠ 全站过滤  
4. 入库与上橱窗两步走  
5. 租户空间 ≠ 资产可见性  
6. 业务用 / 能力建 / 平台治，边界清晰  
7. 材料与 How to 优先，样板间可选  
8. MVP 先能用，深能力后开  
9. 运营低门槛，不为视觉素材设闸  
10. 按钮诚实，精选只排序  

---

## 已固化的领导短期意图（仍属不变层）

**组织视角显性，作用域收敛到自建集市。**

为短期繁荣生态，左侧领域 / 区域必须看得见、点得着；但它服务的是「看我们建了什么」，不是「像 ERP 一样过滤全站」。  
与传统界面习惯冲突时：**保留意图，解释清楚**——既不要强行改成全站过滤，也不要因冲突拆掉左侧显性。

---

## 改版时的快速自检

| 问题 | 若答案是「是」 |
|------|----------------|
| 是否把配置中心当成用户主入口？ | 违反原则 1 |
| 是否让业务用户侧栏堆满治理菜单？ | 违反原则 2、6 |
| 是否让领域/区域过滤外精选/公司推荐本页？ | 违反原则 3（除非明确修订宪章） |
| 是否发布即自动上三货架橱窗？ | 违反原则 4 |
| 是否用租户开关代替资产可见性？ | 违反原则 5 |
| 是否强迫提报填用户看不见的样板间字段？ | 违反原则 7 |
| 是否为「看起来全」默认打开深能力？ | 违反原则 8 |
| 是否强制上传 Logo 才能登记？ | 违反原则 9 |
| 是否用精选角标暗示不可用能力？ | 违反原则 10 |
