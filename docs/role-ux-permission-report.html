业务用户

定位：业务主路径的核心使用者——在业务工作台完成「学习 → 准备 → 开干」，把场景方法落到任务交付。

业务工作台

权限要点

可执行对话 / 打样 技能可执行 专家 / 知识只读 可配置个人模型 API 无能力配置写权限 无系统治理入口

主要功能点

  • 找案例：发现场景与学习内容
  • 场景样板间：学习 / 准备 / 开干三层只读浏览
  • 做任务：选用精选技能 / 专家开工
  • 任务记录：计划确认、执行接力、交付预览
  • 消息：站内触达（MVP 默认可开）

明确不做

  • 不配置专家 / 技能 / 工具货架
  • 不管理展示配置、租户、组织权限
  • 不进入门户内容运营后台
  • MVP 默认不开协作空间（完整方案可开）

主要体验路径

登录（业务壳）→ 找案例→ 进入样板间学习/准备→ 顶栏一键打样→ 任务中心沉淀

备选路径：登录 → 做任务橱窗选精选能力 → 直接开任务 → 交付沉淀。

只读访客

定位：推广与观摩角色——扩大「找案例」覆盖面，只看不跑，降低误操作与算力消耗。

业务工作台 · 只读

权限要点

案例 / 场景只读浏览 对话结果只读 不可发起 / 发送执行 不可配置模型 API 无做任务 / 任务记录菜单（MVP） 无任何配置与治理写权限

主要功能点

  • 找案例：浏览场景与学习材料
  • 场景样板间：只读查看学习 / 准备 / 开干说明
  • 消息：可接收站内信息（若开放）
  • 可下载学习材料（若入口开放），但不打样执行

明确不做

  • 不打开「做任务」开工
  • 不进入任务执行与交付闭环
  • 不修改个人模型与平台配置
  • 不访问运营台任何模块

主要体验路径

登录（业务壳）→ 找案例→ 打开样板间浏览→ 学习方法 / 对照准备清单

路径止于「学与备」；若需开干，须切换为业务用户或由运营侧开放执行权限。

能力运营

定位：平台能力供给者——在运营台把专家 / 技能 / 工具上架并精选露出，保障业务侧「能学、能开干」。

平台运营台

权限要点

工作平台可预览 / 可执行 专家 / 技能 / 工具可写 知识 / 记忆 / 提示词可写（按方案） 设置只读 无展示配置 / 租户配置（超管专属） 无组织权限管理

主要功能点

  • 配置专家 / 技能 / 工具：上架与精选
  • 场景挂载：把能力挂到样板间开干层
  • 预览业务工作台：验证找案例 / 做任务露出
  • 任务中心：抽检打样链路是否可跑通
  • 标准方案可扩展：知识库、自动化等

明确不做

  • 不改侧栏展示方案（超管）
  • 不管理租户数据空间与成员治理
  • 不替代业务用户做日常业务交付
  • 不以个人身份绕过货架发布流程

主要体验路径

登录（运营壳）→ 配置专家/技能/工具→ 发布并精选→ 挂载场景→ 预览业务侧露出→ 抽检一键打样

运营闭环：供给 → 精选 → 挂载 → 验证；与业务「学到干」形成前后台接力。

超级管理员

定位：平台治理者——在能力运营能力之上，负责人、空间、展示与门户边界，保证平台可管可控。

平台运营台 · 治理

权限要点

全部模块 Admin 展示配置（侧栏菜单方案） 租户 / 组织权限 门户内容运营 能力货架全权 可预览业务主路径

主要功能点

  • 展示配置：按角色控制菜单（MVP / 标准 / 完整）
  • 组织权限：成员与角色治理
  • 租户配置：数据空间启用与边界
  • 门户运营：方案 / 培训 / 洞察 / 案例上架
  • 兼具能力运营全部货架能力

明确边界

  • 治理优先于日常业务打样
  • 菜单开放需与 1.0 开放节奏匹配
  • 业务壳菜单仍不塞运营配置项
  • 对外演示边界由展示方案控制

主要体验路径

登录（运营壳）→ 设定展示方案 / 角色菜单→ 组织与租户就绪→ 门户内容上架→ 复核货架精选→ 抽检业务主路径

治理路径强调「先边界、后供给、再验证」；与能力运营协作完成可运行样板。
